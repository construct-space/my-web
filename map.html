The three public rules

1. my.lisaos.dev — the console. All human UIs. All admin REST. Only place users log in.
2. graph.lisaos.dev — the runtime. POST /graphql only. No admin, no schema push, no stats publicly visible.
3. No other public hostnames. developer, accounts, source — all internal-only, reached through my.

Developer space (inside my) — what users see

A single "Developer" area in the console that contains everything:

SectionBacked byExample endpoints
My spaces (list, publish, versions, readme) developer service (its own data) /api/developer/spaces, /api/developer/spaces/:name, POST /api/developer/publish
Schemas for a space (types, fields, indexes) developer → graph internal /api/developer/spaces/:name/schema
Data browser (rows, queries) developer → graph internal /api/developer/spaces/:name/data?model=…
Stats (queries/sec, storage, errors) developer → graph internal /api/developer/spaces/:name/stats
Publisher profile + API keys developer service /api/developer/publisher, /api/developer/api-keys
From the user's perspective, there's no "graph" — there's spaces, and each space has data. From the dev's perspective, there's no "graph URL to admin" — my.c.s/developer is the one place.

What this means for the codebase

AreaChange
my gateway (nginx.conf.template) Drop /api/graph/ location. Drop GRAPH_UPSTREAM env var.
developer service Grow: add /api/schemas, /api/data, /api/stats — each internally calls srv-captain--graph/api/.... Needs GRAPH_INTERNAL_URL=http://srv-captain--graph env.
graph service Stop exposing admin endpoints publicly. Config change: bind admin routes only when X-Internal-Secret present (reject public requests to them). Or run a second listener (public :80 serves only /graphql, internal :8081 serves admin). /graphql public as always.
construct-cli Change schema push/pull endpoints from graph.c.s/api/schemas/* to my.c.s/api/developer/spaces/:name/schema.
my SPA Build the unified "Developer" space — spaces list + schema browser + data browser + stats. One UI, one backend namespace.

Current gateway env vars (after this lands)

INTERNAL_SHARED_SECRET=<shared>
ACCOUNTS_UPSTREAM=http://srv-captain--accounts
DEVELOPER_UPSTREAM=http://srv-captain--developer
SOURCE_UPSTREAM=http://srv-captain--source
# GRAPH_UPSTREAM dropped — graph not proxied through my anymore
Migration order that doesn't break things:
1. developer service grows the façade endpoints (schemas/data/stats internally proxying to graph).
2. my SPA's "Developer" space calls the new façade endpoints (temporarily working alongside direct graph calls).
3. CLI updated to push schemas via developer.
4. graph's public admin endpoints removed / gated.
5. GRAPH_UPSTREAM dropped from my.
Skipping steps = broken CLI / broken admin UI.
